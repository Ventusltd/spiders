# Spiders

This repository is the living Spider species lab for Ventus and GlobalGrid2050 network-topology views.

The federation repository remains the hibernation chamber and recovery source for the first Spider. This repository is where different Spider species can evolve: federation spiders, grid topology spiders, market spiders, source spiders, and eventually the seer spider that can see all other spiders.

Current species planned here:

- federation-spider: the working Spider Sandbox ported from Ventusltd/data-federation-map-for-globalgrid2050-all-repos
- seer-spider: reserved future top-level Spider that can discover and route between Spider species

Pages setup required:

- Enable GitHub Pages for this repository.
- Source: Deploy from branch.
- Branch: main.
- Folder: /root.

Secrets setup:

- No secrets are needed for static Pages serving.
- The sync workflow uses public raw GitHub URLs and the default GITHUB_TOKEN for commits inside this repository.
- Add cross-repo secrets only later if this repo must write back to the federation repository.

Operating law:

The federation repo hibernates and recovers the first Spider. The spiders repo evolves Spider species. No species should pretend to certify engineering truth. Spider outputs are screening-grade views unless a future purchase order explicitly introduces a professional verification layer.

## Cable engines

Ventus is a **cables and connectivity** company, and the clue is in the name. What this estate measures is **cables**: where one starts, where it ends, what route it can take, and what is publicly known about it. Every engine models a cable, and a project's class selects **which question** is asked, never **whether** a question is answered.

| document | what it holds |
| --- | --- |
| [Cable engines](https://github.com/Ventusltd/gridmachine1/blob/main/CABLE-ENGINES.md) | the rule, the priority, and how a project is routed to an engine |
| [Datasheets](https://github.com/Ventusltd/gridmachine1/blob/main/CABLE-ENGINE-DATASHEETS.md) | one contract per engine: question, endpoints, geometry, inputs, outputs, allowed silence |
| [Engineering plan](https://github.com/Ventusltd/gridmachine1/blob/main/ENGINEERING-PLAN.md) | what gets fixed, in what order, and what is protected |
| [Bug register](https://github.com/Ventusltd/gridmachine1/blob/main/BUGS.md) | numbered tickets with links, evidence and status |
| [The capsule](https://github.com/Ventusltd/gridmachine1/blob/main/reports/20260907T230000Z-engine-capsule/README.md) | the working engines sealed with their hashes, and what makes them worth copying |

The five engines: **substation finder within a radius**, **interconnector subsea link**, **offshore export cable to its onshore connection**, **400 kV overhead line and transmission connection**, and **132 kV distribution**. The first and fourth work today and are protected by their own passing receipts.

**The spiders read the same cables.** Network-topology views draw from the voltage layers that the engines measure against: verified 2026-09-07 as OpenStreetMap extracts carrying 4,106 features at 400 kV, 2,935 at 275 kV, 126 at 220 kV, 6,227 at 132 kV, 1,171 at 66 kV and 5,800 substations. Attribution under the Open Database Licence travels with any rendering or export, on the artefact itself.
